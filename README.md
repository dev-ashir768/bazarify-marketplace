# Bazarify

Multi-vendor marketplace frontend: Next.js 16 (App Router, Cache Components), React 19, Tailwind CSS v4, shadcn/ui (Base UI), TanStack Query (+ Devtools), Zustand, React Hook Form and Zod.
The design source is the Figma file *Bazarify Marketplace Website*, page **Bazarify V3**.

```bash
pnpm install
pnpm dev     # http://localhost:3000
pnpm lint
pnpm build
```

## Folder structure

```
app/                      Routes only: thin pages that fetch data and compose features
  (shop)/                 Route group that shares the header and footer layout
    page.tsx              Home / Marketplace
    products/[slug]/      Product detail
    cart/                 Cart + shipping details (checkout)
    checkout/success/     Order confirmation
    wishlist/
  layout.tsx              Root layout: fonts, metadata, providers
  globals.css             Design tokens (brand colors, fonts) and the container-page utility
components/
  ui/                     shadcn primitives. Generated by the CLI; avoid hand edits
  layout/                 Site header, footer, logo, search bar
  shared/                 Reusable pieces with no domain logic (breadcrumbs, quantity stepper, form fields)
features/<domain>/        Everything for one domain: components/, client stores, validation
  home/  product/  cart/  wishlist/
services/                 Data access. Pages call ONLY these functions
mocks/                    Temporary data from Figma. Imported only by services/
schemas/                  Zod schemas: single source of truth for form and API payload types
types/                    Shared TypeScript types (catalog, order)
config/                   Site config (contact, tax rate) and the routes map
lib/                      Helpers: format, query-client, query-keys
hooks/                    Shared React hooks
providers/                QueryProvider (+ Devtools) and zustand store hydration
public/images/            brand/, banners/, products/
```

## Conventions

- **File names:** kebab-case (`product-card.tsx`). **Components:** PascalCase named exports. Default exports are used only where Next.js requires them (page, layout).
- **Server by default.** Add `"use client"` only to interactive leaves (filters, cart, wishlist button).
- **Imports:** use the `@/` alias across folders and `./` inside a feature. A feature may import from `components/`, `lib/` and other features' public components, never from `mocks/`.
- **Links:** build URLs with `routes` from `config/routes.ts`, never hard-coded strings.
- **Styling:** use design tokens (`bg-brand`, `text-ink-muted`, `bg-surface`, `text-sale`, …) defined in `globals.css`, not raw hex values.
- **Money:** prices are PKR integers. Always display them with `formatPrice()`. Discount % and "You save" are calculated from `price` and `compareAtPrice`, never stored.
- **State — pick by where the data lives:**
  - Server data (products, orders) → server components + `services/` now; TanStack Query hooks (`features/<domain>/hooks/use-*.ts`) for client-side fetching and mutations. Keys come only from `lib/query-keys.ts`.
  - Client-only app state (cart, wishlist) → Zustand stores in `features/<domain>/*-store.ts`, read with selectors (`useCartStore((s) => s.items)`). Persisted stores use `skipHydration`; `StoreHydration` loads them after mount, and `useStoreHydrated(store)` gates UI that depends on them.
  - Local UI state (dialogs, filters) → `useState`.
- **Forms:** React Hook Form + `zodResolver`. The schema lives in `schemas/`, and types come from `z.input` (form values) / `z.output` (cleaned payload) — never hand-written twice.
- **Devtools:** the TanStack Query Devtools button shows bottom-right in development only.
- **Next 16 rules:** cache service reads with `"use cache"` + `cacheLife`. Any component that reads `params`, `searchParams`, `cookies` or `headers` must sit inside `<Suspense>`.

## Connecting the API later

1. Add an `apiClient` in `lib/api-client.ts` (base URL from `NEXT_PUBLIC_API_URL`).
2. Replace the mock reads in `services/catalog.service.ts` and `services/order.service.ts`. Keep the function signatures, so no page or component changes. `usePlaceOrder` (TanStack mutation) already wraps `placeOrder`.
3. Parse API responses with Zod schemas in `schemas/` at the service boundary.
4. Once users can log in, sync the cart and wishlist Zustand stores with the API (or move them to TanStack Query).
5. Delete `mocks/`.

## Known gaps (not in the Figma V3 design yet)

Login/Signup, store page, category/search results page, order tracking, account/orders, policy pages, seller and admin dashboards.
Product images in `public/images/products` are crops of the Figma mockup, so some of them still contain the design's badge and heart. Real images will come from the API.
